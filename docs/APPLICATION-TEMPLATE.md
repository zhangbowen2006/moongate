## 一页说明的写作提纲

按这个顺序写，每段 2–4 句即可：

1. **问题**：Agent 通过 MCP 调用本机工具时，读到的密钥可能被下一步发出去；事后看日志已经晚了。
2. **做法**：把网关放在 Agent 与 MCP 服务端之间，判定在转发之前；拒绝意味着上游没有执行。
3. **三层检查**：策略（工具 + 参数）、血缘（值从哪来）、审批（一次、绑定参数）。
4. **技术实现**：判定引擎用 MoonBit；协议解析、策略、血缘、账本、报告同一套代码；JS 只搬字节。
5. **可验证性**：真实进程、真实文件、真实 HTTP 计数；账本哈希链可离线校验；与官方 SDK/官方文件服务端互操作。
6. **边界**：不经过网关拦不住；不做语义 DLP；不是沙箱。写在 SEMANTICS.md 里。
7. **三个使用场景**（必须自己写，见下）。

## 三个使用场景（请本人补全）

每个场景写清楚：谁在用、Agent 想做什么、哪一步被拦下、如果没有网关会怎样。可以从这些方向选，也可以完全换掉：

- **本地资料整理**：Agent 读取含凭据的配置后，试图把内容同步到外部接口；
- **代码仓库维护**：Agent 批量修改文件，删除与推送需要人工确认；
- **数据分析**：Agent 查询数据库后，把结果发到第三方报表服务，策略要求脱敏或审批。

写的时候避免“提升安全性”“赋能”这类空话，直接写动作和后果。
